# Sparkify Data Modeling with Apache Cassandra

This repository completes Udacity's **Project: Data Modeling with Cassandra** for the Sparkify music streaming scenario.

The project builds an ETL pipeline that consolidates raw Sparkify event CSV files into `event_data_new.csv`, then models Apache Cassandra tables around the exact analytics queries requested by the Sparkify team.

## Analytics Questions

1. Find the artist, song title, and song length for `sessionId = 338` and `itemInSession = 4`.
2. Find artist, song title, and user name for `userId = 10` and `sessionId = 182`, sorted by `itemInSession`.
3. Find every user first and last name who listened to `'All Hands Against His Own'`.

## Data Model

Apache Cassandra requires query-first modeling, so the project creates one table per query:

| Query | Table | Primary Key | Why |
|---|---|---|---|
| Query 1 | `songplays_by_session_item` | `(session_id, item_in_session)` | Direct lookup by session and item. |
| Query 2 | `songplays_by_user_session` | `((user_id, session_id), item_in_session)` | Partition by user/session and cluster by item to preserve song order. |
| Query 3 | `users_by_song` | `(song, user_id)` | Direct lookup by song, with user ID preventing duplicate overwrite. |

## Files

- `Project_1B_ Project_Template.ipynb`: completed project notebook.
- `project_1b_solution.py`: script version of the ETL and Cassandra workflow.
- `event_data/`: small sample event data included for local smoke testing. In Udacity Workspace, the full `event_data/` directory is already provided.
- `event_data_new.csv`: generated by the ETL step when the notebook/script runs.
- `requirements.txt`: Python dependencies.

## Run

Start Apache Cassandra locally first. In the Udacity workspace, Cassandra is available at `127.0.0.1`.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python project_1b_solution.py
```

Or open and run all cells in:

```text
Project_1B_ Project_Template.ipynb
```

## Notes

- The included sample CSV is intentionally small but covers all three required query outputs.
- The notebook uses a clean preprocessing flow, filters rows with missing artists, and writes `event_data_new.csv`.
- Tables are dropped at the end of the workflow, matching the Udacity project cleanup step.
